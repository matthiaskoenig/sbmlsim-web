# sbmlsim-web

The renderer of the interactive panels of an SBML model: Vue 3 components which draw a panel - its knobs, its curves and the study data under them - in any HTML page, a documentation site, a slide deck or a course.

A model declares its panels in its own SBML and an [sbmlsim](https://github.com/matthiaskoenig/sbmlsim) endpoint (`python -m sbmlsim.serve`) serves that declaration and runs its simulations. This library talks to such an endpoint, or to a function of the page which answers its routes ([An endpoint inside the page](#an-endpoint-inside-the-page)), and to nothing else, through three versioned JSON contracts:

| contract      | what it carries                                                 |
| ------------- | --------------------------------------------------------------- |
| `panel/1`     | the declaration of a panel and the answer of a simulation of it |
| `paneldata/1` | the study data drawn under its curves                           |
| `app/1`       | the pages of the panels of a model                              |

The documentation is at **https://matthiaskoenig.github.io/sbmlsim-web/**.

`src/contract.ts` is the only place which knows the shape of a payload. The ids of the models, panels, knobs, curves and series are data which come from those payloads, so no model and no entity of a model is built into this library, and `checkContract` refuses a payload of a version it does not speak.

A grid is fetched once per figure and not once per movement of a knob: `interpolate(grid, at)` reads a position between its points locally, multilinear over the axes and clamped to their ends. A point which did not integrate is `null` on the wire with its index in `status.failed`, and it gives `NaN` for the positions it bounds without touching a neighbour it does not bound.

## Quick start

sbmlsim-web needs an endpoint of **sbmlsim >= 0.24.0**, the first release whose service (`python -m sbmlsim.serve`) serves the contracts above. It runs in the browsers which resolve `light-dark()` and lay out CSS subgrids: Chrome and Edge 123, Firefox 120 and Safari 17.5 or newer. An older browser draws the light figure whatever the scheme of the page (a dark page gets it with `theme="dark"`), and the rows of the cards of an app may not line up there.

**Install.** A page loads one script, from a CDN or from the package:

```html
<script src="https://cdn.jsdelivr.net/npm/sbmlsim-web@0.7.0/dist/sbmlsim-web.iife.js"></script>
<sbmlsim-panel
  endpoint="https://models.example.org"
  model="MODEL"
  panel="PANEL"
  auto
></sbmlsim-panel>
```

```bash
npm install sbmlsim-web
```

```js
import 'sbmlsim-web' // registers <sbmlsim-panel>, <sbmlsim-app> and <sbmlsim-figure>
```

The script is pinned to a release (`@0.7.0`), so a page does not change under its readers when a new one is published; `https://unpkg.com/sbmlsim-web@0.7.0` serves the same file. Vue is inlined in every bundle, so a page needs nothing else, and the types (`dist/types`) give `document.querySelector('sbmlsim-panel')` its `activate()`, `freeze()`, `reset()`, `result()` and `drawn()` in TypeScript.

**The endpoint.** A page of another origin than the service is answered only when the service allows its origin, once per origin of the pages which embed it:

```bash
python -m sbmlsim.serve --model hctz=examples.panels.hctz:PROJECT --allow-origin https://docs.example.org
```

A page served by the service itself (`--static DIR`, `endpoint=""`) is one origin with it and needs no `--allow-origin`. The service sheds the requests of a model beyond the ones it holds with a 503 and a `Retry-After`; the element sends such a request again after that time, at most six times, and shows that it loads meanwhile.

**A Zensical (or MkDocs Material) page.** The script is loaded once for the whole site and the element is a raw HTML block of a markdown page, which starts itself (`auto`), also on a page the site swaps in without a reload (instant navigation), where an inline `<script>` which calls `activate()` would run once at most:

```toml
# zensical.toml
[project]
extra_javascript = ["https://cdn.jsdelivr.net/npm/sbmlsim-web@0.7.0/dist/sbmlsim-web.iife.js"]
# optional: the panels take the background of the palette as their surface
extra_css = ["sbmlsim.css"]
```

```markdown
<sbmlsim-panel endpoint="https://models.example.org" model="hctz" panel="renal_plasma" auto></sbmlsim-panel>
```

```css
/* docs/sbmlsim.css */
sbmlsim-panel {
  --sbmlsim-bg: var(--md-default-bg-color);
}
```

The palettes of the theme declare their colour scheme (`slate` is dark), and a panel takes the scheme of the page it is on, so it is light on the light palette and dark on the dark one whatever the system of the reader is. `demo/docs.md` and `demo/zensical.toml` are such a site, which the end to end tests build with Zensical.

**A reveal.js slide.** A deck has every slide in the page, so it starts a panel when its slide is shown and freezes it when the slide is left, which keeps one panel at a time talking to the service; a panel the deck passed over while it loaded finishes when its slide is shown again. `data-prevent-swipe` keeps a drag on a knob from turning the slide, and the element keeps the arrow keys of a knob and of its figure from the deck:

```html
<section>
  <sbmlsim-panel
    endpoint="https://models.example.org"
    model="hctz"
    panel="dose_plasma"
    data-prevent-swipe
  ></sbmlsim-panel>
</section>
<script src="https://cdn.jsdelivr.net/npm/sbmlsim-web@0.7.0/dist/sbmlsim-web.iife.js"></script>
<script>
  const deck = new Reveal()
  const start = (slide) => {
    for (const panel of document.querySelectorAll('sbmlsim-panel')) {
      if (slide.contains(panel)) void panel.activate()
      else panel.freeze()
    }
  }
  deck.on('slidechanged', (event) => start(event.currentSlide))
  deck.initialize().then(() => start(deck.getCurrentSlide()))
</script>
```

```css
/* a dark theme of reveal.js paints dark and declares no scheme: the deck says it is dark */
.reveal {
  color-scheme: dark;
  --sbmlsim-bg: var(--r-background-color);
  --sbmlsim-font-size: 16px; /* every length of a panel follows its two font sizes */
  --sbmlsim-font-size-small: 14px;
}
```

`demo/slides.html` is that deck.

**A Moodle page (HTML block).** The editor of Moodle cleans what an author writes (HTMLPurifier): it removes a `<script>` and an element it does not know unless the author may post trusted content, which a site administrator grants (`moodle/site:trustcontent`). Without it, a page of the panels is hosted elsewhere - a page the service serves with `--static`, or an HTML file uploaded to the course as a File resource - and the HTML block of the course embeds it:

```html
<iframe
  src="https://models.example.org/renal.html"
  title="Hydrochlorothiazide in renal impairment"
  style="width: 100%; height: 520px; border: 0"
  loading="lazy"
></iframe>
```

where `renal.html` is one script tag and one element tag, `demo/plain.html` with the url of the endpoint. With trusted content, the same two tags go into the HTML source of the block (the `<>` button of the editor) and the iframe is not needed.

## The element

A page writes one tag and calls `activate()` on it:

```html
<script type="module" src="sbmlsim-web.js"></script>
<sbmlsim-panel
  endpoint="https://models.example.org"
  model="MODEL"
  panel="PANEL"
  fallback="./stored.json"
></sbmlsim-panel>
<script type="module">
  for (const one of document.querySelectorAll('sbmlsim-panel')) one.activate()
</script>
```

| attribute       | what it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`      | the service the panel talks to; empty is the origin of the page, which is the teaching mode                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `model`         | the id of the model, as the endpoint serves it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `panel`         | the id of the panel of that model                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `variant`       | the variant of the model to simulate, which an app switches between; empty is the one the panel declares; a declaration may differ by the variant, so the panel reads its declaration and its study data in that variant, and a change starts it again: the declaration and the study data are read in the new variant, a knob of its own keeps a value the new declaration takes, and the figure of the variant before is held, dimmed, inert and hidden from a screen reader, with its provenance line, its head and its controls, which take no movement, so the panel keeps its height, until the first figure of the new one is drawn, or dropped at once when its run fails; a value of the host which is a bound or a choice of its knob to the last bits is sent as that number |
| `values`        | the knobs the page owns, a JSON object of knob id to number, e.g. `{"dose": 25}`: the panel sets them, draws no control of them and follows a change of the attribute as it follows a release of its own control; an id the panel does not declare is ignored, and text which is no such object, or a value which is no finite number, is one `console.warn` and leaves the panel as a panel which was never given the attribute: every control is drawn, and a knob the page owned is back at its default                                                                                                                                                                                                                                                                              |
| `head`          | the head the panel shows until it has read its declaration, a JSON object of its `title` and its `subtitle`, e.g. `{"title": "Plasma", "subtitle": ""}`; the shell of an app gives every panel the head the app names for it, so a card shows the head of the variant it is switched to at once, and a text which cannot be read is as if it were absent                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `layout`        | `auto` (the default, the controls beside the figure above 560 px and under it below), `sidebar`, `stacked`, `toolbar`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `size`          | `regular` (the default) or `small`, a figure narrower and lower for a panel of many readouts side by side; the shell of an app writes the size of its page (`AppPage.size` of sbmlsim)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `theme`         | `auto` (the default, the colour scheme of the page), `light`, `dark`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `hover`         | `on` (the default, the crosshair and the readout at the cursor) or `off`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `data`          | `on` (the default, the study data of the panel under its curves) or `off`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `fallback`      | the url of a stored answer of a run, drawn when the endpoint does not answer; it has to be an answer of that panel at the knob values its declaration states, because the payload of an answer carries no knob state and the element therefore reads a stored one at those defaults                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `timeout`       | the milliseconds one request is given, 8000 without                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `heading-level` | the level the title of the panel is drawn at, 2 without; a page writes the level below its own heading here                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `auto`          | a boolean attribute: the element calls `activate()` itself when it is connected, which is what a page with one panel and no script of its own needs; without it nothing is drawn and nothing is requested before `activate()`, because a deck has every slide in the page; the attribute counts by its presence, so `auto="false"` also starts the element, it is read when the element is connected, so adding it afterwards does nothing, and an element which is removed and connected again starts again with fresh requests                                                                                                                                                                                                                                                        |

`activate()` starts it, `freeze()` stops every pending request and freezes the knobs, and `reset()` puts the knobs back to the values the declaration states. A freeze drops no work for good: a second `activate()` reads the declaration a freeze stopped, runs the simulation it dropped or one a knob of the page asked for while the panel was frozen, so a deck which passes over a slide while its panel loads finds it drawn when it comes back. Nothing is fetched and nothing is drawn before `activate()`, so a slide deck or a long page mounts its panels lazily. The element registers itself on import under `sbmlsim-panel`; `register(tagName)` gives it another tag.

**A request grids over at most one knob.** The first run grids over the first `range` knob of the panel at its declared `steps`, with every other knob at its default, and while that knob moves every movement is read out of the grid locally: five moves of it are no request at all. Releasing any other knob schedules one run which grids over **that** knob instead and holds the one which was gridded before at the value it now has, so the knob a reader is working with is always the one which costs nothing. An `input` event interpolates and redraws, a `change` event schedules a run, and a scheduled run which is superseded is cancelled rather than raced. The knob which counts as the gridded one is the knob the run which is scheduled or in flight grids over and not the one the last answer gridded over, so a knob released while a run is on its way gets a run of its own instead of a figure which contradicts it.

**A range knob may name stops on its slider.** A knob of the kind `range` whose `choices` name values inside its bounds - the stages of a renal impairment over a creatinine clearance - draws a select of those stops above its slider, under the one label of the knob: the label names the slider, the select is named by the label and the words `named value`, and both take the keyboard. Picking a stop moves the slider to it and draws the panel there, the slider tells a screen reader the stop it is at (`aria-valuetext` such as `110, normal`), a slider moved onto a stop shows that stop in the select, and a value which is no stop shows the entry `custom`, which is drawn only then and cannot be picked. The slider moves on a ladder which reaches every stop. A range knob without stops is drawn as before, and a knob is the same control in a panel and above the grid of an app. A knob of a dimensionless unit (`dimensionless`, `1`) has its label alone, as a number of no unit. A row of controls - the controls of a panel above or below its figure and the shared controls of an app - is a grid whose items each take two rows of their line, the line of the labels and the line of the bodies, so the options of a panel and the Reset of the shell sit on the line of the selects beside knobs and at the top of a line of their own, whatever wraps where and whatever font the page draws in, and the Reset of the shell takes a column of its own and never width from a control. The shared controls of an app are balanced rows of knobs at their natural width: with `n` knobs and `fit` columns of 200 px fitting the card, the knobs take `ceil(n / ceil(n / fit))` columns in as few rows as fit, which differ by one knob at most, the longer ones first (six knobs fitting five columns are two rows of three, seven fitting three are rows of 3, 2 and 2), and a column is as wide as the card gives it up to 320 px and no wider, so a card of few knobs is not filled; nothing is measured, a container query of the card picks the layout of its width (`columns.ts`). Where the card holds two columns, the Reset sits beside the select of the examples of the page, level with it; on a page without examples it follows the last knob, in a column as wide as itself where the last row has none free and the card holds it beside the knobs at their 320 px; it never narrows a select, and takes a line of its own under the knobs where there is no such room. While a panel has no declaration to draw - before it read its first one, and while it reads the one of the variant a reader switched to - its options, the logarithmic y and the Reset, are disabled with its knobs, since the declaration it reads sets the axis it declares. A knob without a `target` is one the derived values of the simulation read: it is drawn and sent as any other, and the element reads no target.

**The readout is a view of the drawn grid.** A pointer over the figure draws a crosshair at the nearest x of the grid and a box which reads out every curve there, with the colour of the curve, its label and its value with its unit. It costs no request and no interpolation of its own: it shows what the figure already shows. The box never leaves the plot box - it flips to the other side of the crosshair where it would pass the right edge and is clamped at the top and the bottom - and it is laid out on the geometry the renderer drew from (`plotGeometry(spec)`), so it sits on the figure which is there. A plot box too short for one row per curve gets the rows it has room for and a last row reading `+N more`, as a legend label too long for its column ends in an ellipsis; the markers on the crosshair are drawn for every curve whatever the box shows. It follows `pointermove`, so a pen and a finger read a panel as a mouse does, and a device which never moves a pointer simply has no readout. **The readout reads with the keys, too.** The figure is a slider over the x of its grid (`role="slider"`, one stop in the order of the keys, named `Values of` and the title of the figure): the arrow keys move the readout one point, Page Up and Page Down a tenth of the axis, Home and End to its ends, and its value is the readout in words, every curve with its value and unit at that time (`aria-valuetext` such as `120 min: plasma 0.45 uM, kidney 0.38 uM`), which a screen reader announces as it moves, while a sighted reader of the keyboard sees the crosshair and the box where the keys put them. Its description is a summary of the figure, the highest value of every curve and when, and its value at the end. A slider and not a table of the values: a table of five hundred times per curve is no reading anyone does, the slider reads the same points the box shows a pointer, and a screen reader takes the arrow keys of a slider without a mode of its own. The keys it acts on stop at the figure, so a deck does not turn its slide under them; the crosshair and the box are decoration for a screen reader (`aria-hidden`), which reads the value of the slider instead. `hover="off"` leaves the crosshair and the box out, not the slider.

**The study data is one fetch per declaration.** A panel which declares study data reads `paneldata/1` once, when it is activated or reads its declaration again for another variant, model or panel, and draws it as markers with error bars under its curves; it depends on no knob, so it is never read again. The series arrive in the unit the model resolved for the curve they sit under, so nothing is converted in the page; a series which is delivered on a scale of its own is left out, because a figure has one y axis, and three things put it there: it sits under a curve the panel does not draw, e.g. a declaration which names one by a typo, its values are in another unit than that curve, or its x is in another unit than the run. Such a series is no failure of the panel, so it is no error line and no `sbmlsim-error`; the element writes one `console.warn` for it, once per series, which names the series, the curve it sits under and the two units, because the one who can fix a declaration or a study is the one reading the console. A study measures what it measured and a panel simulates the horizon it declares: a point beyond the x of the curves is no point of the figure, it stretches neither axis and draws nothing outside the plot box. A series which declares the state of the knobs it was measured under (`at`) is drawn only while the figure is at that state, so a panel never shows the data of one condition under a curve of another; a knob the state does not name is not constrained, and the state which is compared is the one the drawn answer was run at and never the one the controls are in, since a control changes at once while the figure follows a round trip later. The knob the drawn answer grids over is the exception and needs none: the figure reads a movement of it out of the grid, so its curve and its series move together with the control, and every other knob brings its series back with the answer of its value, so the two halves of the figure are always of one condition. That is no mistake in a declaration, so nothing is written about it. A failed fetch of the study data is no failure of the panel: the curves stay, the overlay is absent, no line is written and no `sbmlsim-error` is dispatched, because nothing a reader asked for failed. `data="off"` asks for none of it.

**Nothing rejects into the page.** A dead network, a slow endpoint, a refused request, a payload of another contract version and a body which cannot be read are all caught inside the element, retried once where that can help, a request the service shed (a 503 with a `Retry-After`) sent again after the time it names, at most six times, while the panel shows that it loads and no error, and resolved into the stored result and one line a reader can act on. The line names no url and no host. A failure is no freeze: the knobs keep working and the next move of any knob runs again. Until a run answers, the figure is drawn only while it is of the state the knobs and the `variant` show; where a knob or the variant stands elsewhere the panel draws no figure, no provenance footer, and its line says that the figure of the settings shown cannot be drawn, so a panel never shows a state no control shows. A change of `endpoint`, `model` or `panel` after the panel started starts it again with what they name. `freeze()` is the one stop of a panel. Reset acts while it changes something, a knob of the panel away from its default or the scale of the y axis; while it would change nothing it says so (`aria-disabled`) and ignores a press, but keeps the focus a keyboard reader pressed it with. The element also dispatches `sbmlsim-error` (`{detail: {kind, message}}`, bubbling and composed) so a page can react. The stored result is fetched on `activate()` next to the declaration and not when a request fails, because an endpoint which cannot be reached cannot serve a fallback either. A stored result has to be an answer of the panel at the knob values its declaration states: the payload of an answer carries no knob state, so the element reads it at those defaults and cannot notice one which was computed at another state.

The element has a shadow root, so the styles of the host page cannot reach it and it cannot leak into the page; the `--sbmlsim-*` tokens are the one hook from outside, and they work from the element and from anything above it. The element declares no token of its own on its host: it reads every one of them into a private token with the value of the design as the fallback, so a documentation theme, the dark switch of a slide deck or a branded container which sets `--sbmlsim-accent` on a wrapper is what the panel takes. A rule of the page which matches the element itself wins over all of it, `theme="light"` and `theme="dark"` come next as the explicit opt-in they are, then an ancestor, then the table of `theme.css`, whose every colour is a pair resolved against the colour scheme of the page (`light-dark()`). The panel takes the scheme the page declares, light for a page which declares none, and not the one of the system of the reader, since a light page under a dark system stays light; a page which follows the system says so (`color-scheme: light dark`). A panel paints the surface of its scheme (`--sbmlsim-bg`), so its text is never read against a page of the other scheme, and a page which wants the panel on its own background sets `--sbmlsim-bg` to it. Every text colour of the table has 4.5:1 and every line 3:1 against every surface of its scheme. Nothing of the typography and nothing of the colour of the panel is declared on the host either, because a declaration of the page which matches the element, `* { font-family: ... }` among them, beats one of the shadow tree there and everything in the panel would inherit it.

## The app shell

`<sbmlsim-app>` is the shell of the app of a model, which replaces a webapp written by hand per model. A page writes one script tag and one element tag, and the model's own declaration (`app/1`, `Project.app` of sbmlsim) is the rest:

```html
<script src="sbmlsim-web.iife.js"></script>
<sbmlsim-app endpoint="https://models.example.org" model="MODEL"></sbmlsim-app>
```

| attribute       | what it is                                                                                                                                                                                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`      | the service the app talks to; empty is the origin of the page                                                                                                                                                                                                               |
| `model`         | the id of the model, as the endpoint serves it                                                                                                                                                                                                                              |
| `page`          | the id of the page which is shown, the first page without or for an unknown id; the shell sets it when a reader switches the page                                                                                                                                           |
| `selection`     | the ids of the panels shown on a page with a figure, comma separated, the panels the page declares as shown without; the app writes it when a reader clicks the figure and dispatches `sbmlsim-selection` with `{ panels }`, a page which sets it restores a state it chose |
| `draws`         | the number of draws of the uncertainty every panel runs with; the draws control of the settings card overrides it for the reader                                                                                                                                            |
| `theme`         | `auto` (the default, the colour scheme of the page), `light`, `dark`, passed to every panel                                                                                                                                                                                 |
| `timeout`       | the milliseconds one request is given, 8000 without                                                                                                                                                                                                                         |
| `heading-level` | the level the title of the app is drawn at, 1 without; its panels are drawn one level below it                                                                                                                                                                              |

It draws the title and the subtitle, the navigation of the pages (a tab row which always ends in the tab `Information`, also for an app of one page), the switcher of the variants (none for an app of fewer than two), the grid of the panels of the page and the provenance footer: the citation, the DOI and the licenses of the declaration and the versions which simulated what is shown, which it reads from the `sbmlsim-result` events of its panels. Every length of the layout of the shell and the panels is in px and none in `rem`, so it does not depend on the root font of the page, which a documentation theme sets to 125 %. The grid has as many columns as fit panels of at least 480 px of the width of the shell, so it is one column below about 976 px of that width and two above, a lone panel takes the row, and an app in a column of a page is as narrow as its column; a page of small panels (`size` of the page, many readouts side by side) has columns of at least 280 px, four in the width of a page, and its panels draw their figures small. The cards of a row share the rows of the grid: the head, the body and the foot of their panels are laid out as subgrids of them through the part `panel` a panel exposes (the parts `figure` and `foot`, its figure and its provenance line, are what the shell dims during a switch of the variant), so the plots of a row line up whatever the lines of their titles and whatever sits under them; a panel alone in a page is laid out as it always is. The rows of a card are reserved before its panel has read anything: the app names the title and the subtitle of every panel of a page (`heads`), the shell lays out a copy of the head of each panel in its card, in the type of the head of the panel and at the width of the card and never shown, so the head row of a row of cards is as tall as its tallest head on the first frame, a panel reserves the height of its figure from its width, and the foot row holds one line of provenance, so a card does not move under the reader while the panels load. The shell paints its own surface, dark under `theme="dark"` and on a page which declares a dark colour scheme, and its text is read against it and not against the page. The shell owns no simulation logic: it reads `app/1`, once per variant a reader chooses, and nothing else, and never simulates; a panel is an `<sbmlsim-panel auto>` which does its own work.

**A knob the panels of a page share is one control.** A knob id which more than one panel of the page declares is drawn once, above the grid, with the control a panel draws, and no panel of the page draws one of it; every panel which declares it gets the attribute `values` with the shared knobs it declares and follows the control, so every plot of the page is of the state the controls show, and a panel whose run failed says it cannot draw that state rather than draw another. A knob id one panel declares stays in that panel, and a panel which declares no shared knob gets no `values` and makes no request when one moves. The service states the shared knobs of each page in the app (`shared`), next to the heads of its panels, and refuses an app whose page declares one knob id differently on two panels, so the shell reads no declaration of a panel and a panel which cannot be read changes nothing of the controls of its page. The shared controls sit in a settings card above the grid, which also holds the logarithmic switch of every plot, the draws control, the one Reset of the page (the shared knobs, the scale, the draws and the own controls of the panels, the selection kept) and the line of the last run; a screen reader hears the titles of the panels a control sets. A panel embedded alone draws every control it declares.

**A page may show the figure of the model.** A page with `figure` draws the `<sbmlsim-figure>` of the app beside its grid, and a click on a part of it adds the panels it opens or removes them; the shell keeps the choice in the attribute `selection` and dispatches `sbmlsim-selection` with the ids of the panels shown, also when a change of the page or of the variant puts the selection back to what the page declares as shown. A part of the drawing which opens no panel of the page is decoration, not a control.

**An app has an information view.** The last tab, `Information`, is a value of `page` (`page="information"`, with `sbmlsim-page` as any tab emits): it shows the title, the citation, the licenses and the versions which simulated the app, and stops the panels until a page tab brings them back.

**A page may name scenarios of its knobs.** A page whose `scenarios` name states of its shared knobs - example patients - draws a select of them, labelled `Example`, above the controls they set. Picking one sets every knob it names in one state, so a panel runs at most once for it however many of its knobs moved, and leaves every knob it does not name where it is. The select shows the first scenario whose every value is the value its knob has, else the entry `custom`, which is drawn only then and cannot be picked; Reset puts the knobs back to their defaults and the select follows. A page without scenarios draws nothing of them.

**A page change swaps the panels in the grid.** The panels of the page which is left are frozen and removed, and the panels of the page which is shown start themselves, so the DOM holds the panels of one page. A panel is created again when its page is returned to, with its knobs and the shared knobs of the page at the values of their declaration, and the endpoint answers its first grid from its cache.

**The app follows the variant.** The declarations of the panels may differ by the variant of the model, and so may the knobs a page shares, its scenarios and the heads of its cards: a switch of the variant reads the app again in it (`?variant=`), and the app names the variant it answers (`variant`), which the shell checks against the one it asked for and keeps, so the app of every variant, the first one included, is read once. While the app is read, the panels keep the figures of the variant before, dimmed, inert and hidden from a screen reader (`inert`, `aria-hidden`), with a caption beside the switcher which names the variant they are switched to ("Switching to ... …", whose room, that of the longest caption of any variant, is kept at all times), the provenance line of their answers stays as well, dimmed as they are, the shared controls and the tabs take no movement, and nothing of the page moves. When it arrives the controls, the scenarios and the heads are of that variant, a shared knob keeps its value where it is a knob of that variant which takes it and starts at its default otherwise, and the panels get the variant and those values at once; each holds its figure of the variant before, dimmed, until it draws one of the new variant, and the caption and the dimmed provenance line stay until every panel of the page has drawn or failed; the answer of a panel which failed is dropped from the line as its figure is. An app of a variant which cannot be read leaves no figure of the variant before (the panels keep their room and are not drawn) and a line which says so, and switching back to the variant which was drawn draws it again without a request.

**The chosen variant goes to every panel.** It is the `variant` attribute of the panels, which send it in the body of the simulation, and it stays chosen while the page changes.

**A failure leaves one line.** An app which cannot be read - an endpoint which is down, a model without an app, a payload of another version - shows one line in the voice of the panel, which names no url, no host and no status, and no navigation, grid or footer; `sbmlsim-error` is dispatched as a panel does.

**A curve carries a band where its model knows its parameters to a range.** A model of a fit knows its parameters to an interval and not to a number, and a panel whose declaration says so (`PanelUncertainty`: the draws the endpoint holds a sample of, the fit they come from and the level of the band) asks for that many draws and shades the percentiles of the answer under every curve, in the colour of the curve. The band travels for every point of the grid, so a reader who moves a knob sees it move with the curve rather than behind it, and `drawn().bands` hands the shaded range to a readout which states it in numbers. The `draws` attribute of a panel, and of an app for every panel of its page, is how many draws a page asks for: absent is the number the declaration states, `0` is no band, and more than the sample holds is what it holds, so one control of a page lets a reader trade the smoothness of the band against the cost of the draws.

A panel dispatches `sbmlsim-result` for every successful simulation, never for a failure and never for a stored fallback: the `panel` which answered, the `provenance` and the `spec_hash` of the run and the `values` of the knobs it was run at, which is the state it was sent at and not what the controls hold by the time the answer arrives. `result()` of that element is the run itself, a copy of the answer its figure was drawn from. A readout of the page which computes something the panels do not draw - a table of pharmacokinetic parameters, a ratio, a sum - follows `sbmlsim-shown` instead, which a panel dispatches whenever what it draws changed, after a run and after a movement of a knob the drawn grid covers, which fetches nothing; `drawn()` is that figure, one curve per id at the position of the controls with the band of every curve which carries one, read out of the grid as the figure is, so a readout works from the curves the reader sees and never simulates a second time. The shell dispatches `sbmlsim-page` with `detail.page`, the id of the page, when a reader switches the page (not when a page sets the attribute itself), which lets a deployment give its pages addresses and answer the back button by setting `page` again, and it announces the switch to a screen reader in a polite live region. `register(tagName, appTagName, figureTagName)` gives any of the elements another tag, and the shells place their panels under `tagName`. `<sbmlsim-figure>` draws the figure of an app (`figure`, `marked` and `labels` are its properties) and dispatches `sbmlsim-figure-select` with `detail.key`, the key path of the control a reader clicked, the `data-k` keys of the drawing joined with `/`; the paths in `marked` are drawn as on screen.

## An endpoint inside the page

An `endpoint` which starts with `local:` is no server: it is answered by a function of the page itself, which the page registers under that exact name with `registerEndpoint(endpoint, fetcher)`. This is how a static page (GitHub Pages, a course, a file share) runs the panels of a model without a service: the function answers the routes of `python -m sbmlsim.serve` inside the page, e.g. on a simulator which runs in Web Workers in the browser of the reader ([sbmlsim-core](https://matthiaskoenig.github.io/sbmlsim-core/) has such a function, `createPanelEndpoint` of its `js/panels.mjs`, which answers the routes from a bundle the service exports).

```html
<script src="https://cdn.jsdelivr.net/npm/sbmlsim-web@0.7.0/dist/sbmlsim-web.iife.js"></script>
<sbmlsim-app endpoint="local:glimepiride" model="glimepiride"></sbmlsim-app>
<script type="module">
  import { createPanelEndpoint } from 'https://cdn.jsdelivr.net/npm/sbmlsim-core@0.6.0/panels.mjs'
  sbmlsimWeb.registerEndpoint(
    'local:glimepiride',
    createPanelEndpoint({ bundle: new URL('./bundle/glimepiride/bundle.json', location.href) }),
  )
</script>
```

```js
import { registerEndpoint } from 'sbmlsim-web'

registerEndpoint('local:demo', async (url, init) => {
  // url: 'local:demo/api/models/MODEL/panels/PANEL', init: { method, headers, body, signal, ... }
  return Response.json(answerOf(url, init))
})
```

`registerEndpoint` is in the releases from 0.2.0 on, and both scripts are pinned to a release, as on any page; the npm package `sbmlsim-core` starts the workers of its pool from a module of the page's origin, so it runs from the CDN as well, and only the bundle (`bundle.json` and the compiled model) is a file of the site. The function has the signature of `fetch` (`EndpointFetch`, `(url: string, init: RequestInit) => Promise<Response>`). The client calls it with the url of the route, the endpoint joined with the path of the route (`local:demo/api/models/MODEL/panels/PANEL/simulate`, with `?variant=` where a route is read in a variant), and with the `init` it would give `fetch`: the method, the headers, the body of a POST as JSON text and the signal which stops the request. Its `Response` is read exactly as one of the network: a status which is no success is an `http` failure, a 503 with a `Retry-After` is sent again after that time, the body is parsed as JSON, its `contract` is checked and its shape is guarded, and the request is bounded by the `timeout` of the element. A rejection of the function is a `network` failure, and a function which does not listen to its signal is stopped all the same, by its timeout or by the element which superseded the request.

An element may connect before its endpoint is registered, which is what a page does whose module script registers it: the requests of the element wait for the registration, within their timeout and their signal, and are sent to the function as soon as it is there. A second registration of a name replaces the first for the requests sent after it, a trailing slash is no part of the name (`local:demo/` is `local:demo`), and registering a name which does not start with `local:` throws a `TypeError`, so a url of the network is never answered by the page. The `fallback` of a panel is a file of its own and is always fetched over the network.

## The renderer

`plotSvg(spec)` draws a figure as one inline SVG string: the axes with their ticks and their units, one path per curve, the study data as markers with error bars under them, whose shape is the position of a series among the ones of its curve, so two studies under one curve share its colour and are told apart by their markers, and a legend of up to ten curves or, above them, a colour bar, which is where sbmlsim draws one. It is pure - a string in, a string out, no dom, no canvas and no plotting library - so the same figure is built in a page, in a test and in a worker, and it stays crisp under the transform of a slide. The one thing it cannot know is how wide its text is drawn, since that is the font the page resolves: every width it lays out with - a tick label, the lines of an axis label, a legend entry, the rows of a legend and their centring, the column beside the plot - is asked of the `measure` of its spec, a function `(text, size) => pixels`. The element passes one built on canvas `measureText` in the font it draws its figure in (`canvasMeasure` of `fontOf` the panel), and lays its figure out once more when a font which was still loading has arrived; a spec without a measure is measured with the advance widths of Arial (`tableMeasure`), so a figure without a dom is still one exact figure. The sizes the text is drawn in are an input as well (`fontSizes`, the label and the small size): every width is measured at the size of its text and every line, row and margin is as tall as its font, so a page which sets `--sbmlsim-font-size` and `--sbmlsim-font-size-small` gets a figure laid out for them; the element passes the sizes those tokens resolve to. A logarithmic axis follows the rule of sbmlsim (at most six decades below the largest value), so a web figure and a matplotlib figure of the same data have the same limits. `plotGeometry(spec)` gives the layout that figure was drawn from - its plot box and the pixel of a value on either axis - so a caller which draws a crosshair, a readout or a marker of its own over a figure places it on the figure which is there and not on one it had to guess at. A figure takes the limits of its value axis from what it draws, or from the `yLimits` of its spec, which is what a caller passes which draws one of several lines of one answer at a time: a line then moves inside a frame which holds still instead of redrawing itself inside a frame which follows it, and the rule of the decades applies to that frame. A panel which declares the ends of its axes (`y_min`, `y_max`, `x_max`) gets them as `yEnds` and `xEnd`, which are no frame but the ends of the axis exactly: the axis runs from the one to the other with its ticks inside, so two states of the knobs are drawn against one axis, a curve or a point beyond them is cut at the plot box and drawn over no margin, legend or label, and study data beyond `xEnd` is no point of the figure; where one end is declared the other is derived as without, and on a logarithmic axis the ends are the ends of its decades, a declared end which is not positive being none there. A legend sits beside the plot or below it, packed into the rows of the figure, whichever of the two leaves the larger plot box: that is a column on a figure which is wide and short and a band of rows on the figure of a panel, and comparing the two is what keeps a figure which grows from ending up with a smaller plot than it had. A colour bar keeps its column either way. A figure of one curve and no study data, drawn or declared, has no legend, since its one entry would name the quantity its y label names; a figure of two or more curves, or with study data, keeps its legend and lays it out as before. What a panel may draw is decided by its declaration and not by the study data it has received: the legends it reserves are the labels and the states of its declared series, so a panel of one curve with study data holds its legend from its first figure whether the run or the data answers first, and the data only decides which points are drawn. A panel whose value axis holds its study data, one which does not fix both ends of the axis, draws its first figure once the data has arrived or failed to, so the axis is laid out once; a panel whose axis is fixed draws its curves as soon as they run. The legend is laid out over the legends of `declaredLegends`, each the labels a state of the caller draws together in the order it declares them: the band keeps the rows of the legend which needs the most and the column the width of the widest label of any, and the figure draws the legend it has, so a figure keeps its plot box whichever of them is drawn and keeps the room of the largest legend one state draws, not of every series at once. A legend below the plot spans the plot box and centres its rows on it, as the label of the x axis above it is centred, so the plot, its label and its legend read as one block. The label of an axis wraps at its words onto two lines of the length of that axis rather than being cut, and the margins of a figure are grown by what its tick labels need beyond them, an x axis asks for fewer ticks where its measured labels would run into each other, always keeping its first and its last, every tick label starts on a whole pixel, at most half a pixel from where its tick centres it, so equal glyphs are drawn in one tint where a browser antialiases text by subpixels, and a layout which could draw its last tick alone, a number without a second one to read a scale from, is no candidate where the other layout draws both, so the label of the last tick stays inside the figure instead of being cut at its edge; that is `_fit_margins` of sbmlsim, so the two renderers answer a narrow figure the same way.

Every colour, font and stroke width of a figure is a `--sbmlsim-*` token whose fallback is the value of the style of the sbmlsim reports, so a page which loads nothing still gets the figure of a report. `src/theme.css` (`sbmlsim-web/theme.css`) carries those tokens in light and dark, and a page which sets one of them on the element it draws a panel in gets the figure in its own colours.

## Build

```bash
npm ci
npm run lint       # eslint and prettier
npm test           # vitest
npm run typecheck  # the whole project, the tests included
npm run build      # dist/sbmlsim-web.js (ESM), .umd.cjs (UMD), .iife.js (IIFE), dist/types, checked against package.json
npm run e2e        # the demo pages in Chrome against a live endpoint, see below
npm run format     # write what prettier wants
npm run docs       # the build and the documentation site into site/ (Zensical through uvx)
npm run docs:serve # the build and a preview of the documentation site
```

Vue is bundled into every build, so a host page needs nothing else: it reads `dist/sbmlsim-web.js` with a `<script type="module">` or through a bundler, `dist/sbmlsim-web.umd.cjs` is the same library for a `require`, and `dist/sbmlsim-web.iife.js` is the one for a page which wants the `sbmlsimWeb` global from a plain `<script src>`, which a static server serves as a script where it serves a `.cjs` file as a download.

Vue is no dependency of the package but a development dependency of the build: every bundle inlines it, and the published types import nothing of it (`scripts/check-package.mjs` checks both after every build, together with every entry point `package.json` names), so a consumer installs no Vue for the elements and a page which runs a Vue of its own gets no second copy of it in its dependencies. The elements are custom elements with shadow roots, which share nothing with a Vue app of the page, so the price is the copy of Vue a page with a Vue of its own loads beside it.

The documentation site is `docs/` with `zensical.toml`: `scripts/docs.mjs` copies `dist/sbmlsim-web.iife.js` into the ignored `docs/assets/sbmlsim-web/`, which every page loads, and builds the site with Zensical (`uvx --from zensical==0.1.0`) into the ignored `site/`, which the workflow `docs` publishes to GitHub Pages from `main`. An example goes into `docs/examples/` as a page with its assets in a folder of its name.

A release is a tag `vX.Y.Z` of the version of `package.json` with its notes in `release-notes/X.Y.Z.md`: the workflow `publish` runs the checks of `ci` for the commit of the tag, the end to end tests included, and publishes the package to npm with its provenance.

## The demo pages and the end to end tests

`demo/` has the four pages the elements are tested on, the three hosts of the panel and the page of an app: `plain.html` (one script tag and one element tag, the page of a course platform), `slides.html` (reveal.js on a dark theme, which activates a panel when its slide is shown and freezes it when it is left) and `docs.md` (a raw HTML block in a markdown page, which `scripts/stage-demo.mjs` builds into `docs.html` with Zensical and the site of `demo/zensical.toml`, through `uvx`), and `app.html` is the page a model deployment serves: one script tag and one `<sbmlsim-app>` tag. `npm run e2e` stages them and serves them with the endpoint of the python package, `python -m sbmlsim.serve --static`, so a page and its API are one origin, and drives the installed Chrome through playwright. The endpoint is the checkout in `SBMLSIM_REPO` (`../sbmlsim` without), serving `examples.panels.hctz:PROJECT`; where there is no such checkout the command says that it skipped and exits 0 on a machine of a developer, and fails under continuous integration (`CI=true` or `CI=1`), unless `SBMLSIM_E2E_OPTIONAL=1`. The workflow `ci` checks sbmlsim out at the release it pins (`SBMLSIM_REF`), installs its service with uv and runs the suite. `e2e/contract.spec.ts` compares what the service answers with `src/fixtures/contract.json`, the payloads `src/contract.test.ts` reads through the client, so a change of the contracts on either side fails a test; `UPDATE_CONTRACT_FIXTURE=1 npm run e2e -- contract` writes the fixture again.
