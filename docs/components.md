# Components

The package registers three custom elements when it is imported: `<sbmlsim-panel>`, one panel of a model, `<sbmlsim-app>`, the app of a model, which places panels itself, and `<sbmlsim-figure>`, the drawing of a model as a control. All have a shadow root, so the styles of the page cannot reach into them and theirs cannot leak into the page; the `--sbmlsim-*` tokens are the one hook from outside ([Embedding](embedding.md#theming)).

## `<sbmlsim-panel>`

```html
<sbmlsim-panel
  endpoint="https://models.example.org"
  model="hctz"
  panel="renal_plasma"
  fallback="./renal_plasma.json"
  auto
></sbmlsim-panel>
```

### Attributes

| attribute       | default   | what it is                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`      | empty     | the endpoint the panel talks to, e.g. `https://models.example.org`; empty is the origin of the page (a page the service serves itself), and one which starts with `local:` is answered by a function of the page ([Endpoints](endpoints.md))                                                                                                                                                               |
| `model`         | empty     | the id of the model, as the endpoint serves it                                                                                                                                                                                                                                                                                                                                                             |
| `panel`         | empty     | the id of the panel of that model                                                                                                                                                                                                                                                                                                                                                                          |
| `variant`       | empty     | the variant of the model to simulate, empty for the one the panel declares; the panel reads its declaration and its study data in that variant, and a change starts it again in the new variant, holding the figure of the variant before, dimmed, until the first figure of the new one is drawn                                                                                                          |
| `values`        | none      | the knobs the page owns, a JSON object of knob id to number, e.g. `{"dose": 25}`: the panel sets them, draws no control of them and follows a change of the attribute as it follows a release of its own control; an id the panel does not declare is ignored, and text which is no such object, or a value which is no finite number, is one `console.warn` and leaves the panel as if it had no `values` |
| `head`          | none      | the head the panel shows until it has read its declaration, a JSON object of its `title` and its `subtitle`, e.g. `{"title": "Plasma", "subtitle": ""}`; the shell of an app sets it, so a card shows its head at once                                                                                                                                                                                     |
| `layout`        | `auto`    | where the controls go: `auto` (beside the figure above 560 px of width and under it below), `sidebar`, `stacked` or `toolbar`                                                                                                                                                                                                                                                                              |
| `size`          | `regular` | the size of the figure: `regular`, or `small` for a panel of many readouts side by side, narrower and lower; the shell of an app writes the size of its page                                                                                                                                                                                                                                               |
| `compact`       | `false`   | a property, not an attribute: `true` draws the card as a plot and nothing else, without its options, without the line of its run and with its controls only where it has knobs of its own, for a page whose shell carries the switch, the draws, the freeze and the reset of every panel; the shell of an app sets it on every panel of a page which draws a figure                                        |
| `theme`         | `auto`    | which values of the tokens are used: `auto` (the colour scheme of the page), `light` or `dark`                                                                                                                                                                                                                                                                                                             |
| `hover`         | `on`      | `on` draws the crosshair and the readout at the pointer, `off` leaves them out (the keyboard readout stays)                                                                                                                                                                                                                                                                                                |
| `data`          | `on`      | `on` draws the study data of the panel under its curves, `off` asks for none of it                                                                                                                                                                                                                                                                                                                         |
| `fallback`      | empty     | the url of a stored answer of a run (`panel/1`), drawn when the endpoint does not answer; it has to be an answer of that panel at the knob values its declaration states, and it is always fetched over the network                                                                                                                                                                                        |
| `timeout`       | `8000`    | the milliseconds one request is given before it is stopped                                                                                                                                                                                                                                                                                                                                                 |
| `draws`         | absent    | the draws of the uncertainty of the panel its curves carry a band of: absent is the number its declaration states, `0` is no band, and a number above the sample of the endpoint is that maximum; a change of it runs the panel again, since the draws are part of what a run answers, and a panel of a model which declares no uncertainty draws no band whatever it says                                 |
| `log`           | absent    | the scale of the y axis the host asks for, `true` or `false`; absent is the scale the curves declare. The panel starts at it and goes back to it on a reset, a change of it sets the axis, and its own switch may change it again; a panel whose curves do not share one scale keeps the axis its declaration gives it. The shell of an app writes it for the logarithmic switch of its page               |
| `heading-level` | `2`       | the level the title of the panel is drawn at; a page writes the level below its own heading here                                                                                                                                                                                                                                                                                                           |
| `auto`          | absent    | a boolean attribute: the element calls `activate()` itself when it is connected; it counts by its presence (`auto="false"` starts it as well) and is read when the element is connected, and an element which is removed and connected again starts again                                                                                                                                                  |

A change of `endpoint`, `model` or `panel` after the panel started starts it again with what they name.

### Methods

| method                  | returns                    | what it does                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activate()`            | `Promise<void>`            | starts the panel: reads its declaration, its study data and its fallback and runs its first simulation; on a frozen panel it lifts the freeze and does what the freeze dropped, so a deck which passed over a slide finds its panel drawn; it resolves when the first figure is drawn or the failure is shown, and never rejects                                                                           |
| `setLog(on)`            | `void`                     | sets the scale of the y axis as a click on the switch of the panel does, where its curves share one scale; the attribute `log` is what a panel starts and resets at, this moves a panel whose own switch was flipped since                                                                                                                                                                                 |
| `freeze()`              | `void`                     | stops every pending request and freezes the knobs; it drops no work for good                                                                                                                                                                                                                                                                                                                               |
| `reset()`               | `void`                     | puts every knob back to the value its declaration states and the y axis back to the scale its curves declare; a knob the page owns (`values`) keeps the value of the page                                                                                                                                                                                                                                  |
| `keep(id, rank, label)` | `boolean`                  | keeps the curves of the panel as they are drawn now, so the ones which come are read against them: the run is drawn under the live curves in their colours, dashed by its `rank` (from 1) and named `label` in the legend, and `id` is what drops it again; `false` where the panel has drawn nothing, which is the one case it keeps none                                                                 |
| `drop(id)`              | `void`                     | drops the run of that id                                                                                                                                                                                                                                                                                                                                                                                   |
| `clearKept()`           | `void`                     | drops every run it kept, which a page does when it is left or its variant is switched                                                                                                                                                                                                                                                                                                                      |
| `drawn()`               | `DrawnFigure \| null`      | the figure this panel draws, one curve per id at the position its controls stand at, read out of the grid of the last run exactly as the figure is (`interpolate`), or `null` while it draws nothing; `bands` carries the band of every curve which has one, read at that same position, so a readout states the range the figure shades; a readout of the page computes from it and never simulates again |
| `result()`              | `SimulateResponse \| null` | the answer of the last simulation of this panel, a copy, or `null` before the first one, for a failure and for a stored fallback; a readout which computes something of its own from the curves a panel drew reads it here instead of running the same simulation again                                                                                                                                    |

### Events

| event            | `detail`                                          | when                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sbmlsim-result` | `{ panel, provenance, draws, spec_hash, values }` | a simulation succeeded and its figure is drawn; never for a failure and never for a stored fallback, which is no simulation. `panel` is the id of the panel which answered, `draws` the draws the run asked for (`0` for none) and `values` the knob values the run was made at, whatever the controls hold by the time it arrives; `result()` of the same element is that run |
| `sbmlsim-shown`  | `{ panel, values }`                               | what a panel draws changed: the answer of a run, a movement of a knob the drawn grid covers, which fetches nothing, and the stored fallback of a declaration. `drawn()` of the same element is that figure, and a readout which follows the controls listens to this and not to `sbmlsim-result`, which only a simulation dispatches                                           |
| `sbmlsim-scale`  | `{ panel, log }`                                  | the scale of the y axis of the panel is set or changed (its declaration, a click on its own switch, the attribute `log`, `setLog()`); `log` is whether it is logarithmic. The shell of an app reads it to show the page switch                                                                                                                                                 |
| `sbmlsim-error`  | `{ kind, message }`                               | a request failed; `kind` is a failure kind (below) and `message` the one line the panel shows                                                                                                                                                                                                                                                                                  |

Both bubble and are composed, so they reach the page out of the shadow root of a panel which an app placed.

### Parts

The panel exposes three parts for `::part()`: `panel` (the whole panel, whose head, body and foot an app lays out as subgrids of its rows), `figure` (the figure) and `foot` (the provenance line).

### What it does

- **A request grids over at most one knob.** The first run grids over the first `range` knob at its declared `steps`, with every other knob at its default, and every movement of that knob is read out of the grid without a request. Releasing another knob runs one simulation which grids over that knob instead, at the value the others now have. An `input` event interpolates and redraws, a `change` event schedules a run, and a scheduled run which is superseded is cancelled.
- **A range knob may name stops.** A range knob whose `choices` name values inside its bounds draws a select of those stops above its slider; picking one moves the slider there, and a value which is no stop shows `custom`.
- **The readout is a view of the drawn grid.** A pointer over the figure draws a crosshair at the nearest time of the grid and a box with the value of every curve there. The figure is also a slider for the keyboard (`role="slider"`): the arrow keys move the readout one point, Page Up and Page Down a tenth of the axis, Home and End to its ends, and a screen reader hears the values of every curve.
- **The study data is one fetch per declaration.** It arrives in the unit of the curve it sits under; a series of another unit or under a curve the panel does not draw is left out with one `console.warn`, and a series which declares the state of the knobs it was measured under (`at`) is drawn only at that state.
- **A curve carries a band where its model knows its parameters to a range.** A panel whose declaration carries an uncertainty (`PanelUncertainty`: the draws a request without a number gets, the draws of the sample of the endpoint, the level of the band and the seed it was drawn with) asks its endpoint for that many draws and shades the percentiles the answer carries under every curve, in the colour of the curve. The band travels for every point of the grid, so it moves with the curve as a knob moves and not behind it; `draws` is how many of them a page asks for and a movement of it runs the panel again, `0` is none, and `drawn().bands` hands the shaded range to a readout. The fit the draws come from is of the model and travels with an answer (`uncertainty.fit`), which `result()` hands out; for a run of a single point the answer also carries the curves of the draws themselves (`uncertainty.curves`), so a reader of the page can compute what a band cannot state - the parameters of every draw, whose percentiles are not the parameters of the percentiles.
- **Nothing rejects into the page.** Every failure is caught inside the element and shown as one line which names no url and no host; a request the endpoint shed (a 503 with a `Retry-After`) is sent again after the time it names, at most six times, while the panel shows that it loads. A failure is no freeze: the next move of a knob runs again.

## `<sbmlsim-app>`

```html
<sbmlsim-app endpoint="https://models.example.org" model="hctz" page="renal"></sbmlsim-app>
```

### Attributes

| attribute       | default | what it is                                                                                                                                                                                                                          |
| --------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`      | empty   | the endpoint the app and its panels talk to; empty is the origin of the page, `local:<name>` a function of the page                                                                                                                 |
| `model`         | empty   | the id of the model, as the endpoint serves it                                                                                                                                                                                      |
| `page`          | empty   | the id of the page which is shown, or `information` for the information view, the first page without or for an unknown id; the shell sets it when a reader switches the page                                                        |
| `selection`     | absent  | the ids of the panels of the page which are shown, comma separated, on a page which shows the figure of the model; absent is the panels the page declares as shown, empty none; the shell writes it when a reader clicks the figure |
| `theme`         | `auto`  | `auto` (the colour scheme of the page), `light` or `dark`, passed to every panel                                                                                                                                                    |
| `timeout`       | `8000`  | the milliseconds one request is given, passed to every panel                                                                                                                                                                        |
| `draws`         | absent  | the draws of the uncertainty every panel of the page asks for, absent for the number each of them declares; one control of a page moves the bands of its figures together, and every panel runs again on a change of it             |
| `heading-level` | `1`     | the level the title of the app is drawn at; its panels are drawn one level below it                                                                                                                                                 |

The shell has no methods: it starts itself when it is connected and is driven by its attributes alone.

### Events

| event               | `detail`            | when                                                                                                                                                                                    |
| ------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sbmlsim-page`      | `{ page }`          | a reader switched the page; not when the page sets the attribute itself                                                                                                                 |
| `sbmlsim-selection` | `{ panels }`        | a reader clicked the figure: the ids of the panels now shown, in the order of the page, or a page change reset it to the new page's panels; not when the page sets the attribute itself |
| `sbmlsim-error`     | `{ kind, message }` | the app could not be read (an endpoint which is down, a model without an app, a payload of another version)                                                                             |

The events of its panels (`sbmlsim-result`, `sbmlsim-error`) bubble out of the shell as well. `sbmlsim-page` lets a deployment give its pages addresses and answer the back button by setting `page` again:

```js
const app = document.querySelector('sbmlsim-app')
app.addEventListener('sbmlsim-page', (event) => {
  history.pushState(null, '', `#${event.detail.page}`)
})
addEventListener('popstate', () => app.setAttribute('page', location.hash.slice(1)))
```

### What it does

- **It draws the app of the model.** The title and the subtitle, the navigation of the pages (a tab row, always drawn since it ends in the tab `Information`), the switcher of the variants (none for fewer than two), the grid of the panels of the page, as many columns as fit panels of at least 480 px (280 px and a small figure for a page of `size` `small`, many readouts side by side), and the provenance footer: the citation, the DOI and the licenses of the app and the versions which simulated what is shown.
- **A knob the panels of a page share is one control.** It is drawn once above the grid and every panel which declares it follows it (through its `values`), so every plot of the page is of the state the controls show.
- **One card holds what every plot of the page shares.** Above the grid, in the same stage as the figure, a card has the logarithmic switch of every plot, the draws control, the Reset of the page and the line of the last run, its seconds and its engine, read from the provenance the shell collects of every answer (the latest by its `created` time). The switch shows the state the plots are in: checked where every plot is logarithmic, unchecked where none is, indeterminate where they differ, and a click sets all of them (it writes `log` on every placed panel, also on one placed later, and sets the axis of the ones placed); a panel whose curves do not share one scale keeps its own axis, so a page of such panels stays indeterminate and its second click turns the others off. The draws control shows the draws in effect: the most the last runs were made with, so a number above the draws the sample of the endpoint holds shows the ones held to, and before any run the number the reader typed or the attribute `draws`; a typed number overrides the attribute for every panel, a negative number is `0` (no band), a decimal is cut to its whole part, and an empty or invalid text goes back to the attribute. The control is hidden once every placed panel which ran reports no draw, which is a model with no uncertainty where it could only say zero, and drawn again when one reports more or the attribute is set; before the first run it holds its place without its text, so the card does not change its height. A panel without an uncertainty draws no band whatever the number is. The panels keep their own switch and their own Reset. The Reset of the page is the only Reset above the grid and has no idle state, so it is not dimmed because nothing changed, and is disabled only while a switch of the variant is under way: it puts the shared knobs, the scale and the draws of the page and the own controls of every placed panel back, and keeps the selection. A change of the page puts the scale and the draws of the card back as well. The card also freezes the curves of the page: `Freeze` keeps the curves of every panel as they are drawn now (`keep(id, rank, label)` of every placed panel, one id and one rank for the page), so they stay in their plots as dashed curves in their own colours while the knobs move on, at most four of them, one dash each; the card shows a chip per frozen run with that dash, the state of the shared knobs it was frozen at (every knob as a reader reads it: the label of the choice or of the stop it stands on, else its number and its unit, cut with an ellipsis where it is longer than the chip and whole in its title) and a cross which drops it (`drop(id)`), `Drop all` drops them, and a switch of the page or of the variant drops them as well, since the curves of a run belong to the panels and the model it was frozen in. On a page which draws a figure the card also has `Clear selection`, which shows the panels the page declares and forgets what a click on the drawing picked, dimmed while nothing is picked. The parts are `settings`, `settings-log`, `settings-draws`, `settings-draws-input`, `settings-freeze`, `settings-frozen`, `settings-clear`, `settings-reset` and `settings-run`.
- **An app has an information tab.** The last tab of the row, `Information`, is there for every app, one page included: the row then holds the page and Information. It shows the title, the subtitle, the citation, the DOI, the licenses and the variants of the app with the versions which simulated it and the line of the last run, all read from the declaration and the provenance; nothing is authored for it. While it is shown the provenance footer is hidden, since it says the same, the panels are stopped and hidden, and a click on a page tab starts them again. The information is a value of the page machinery: the tab sets `page="information"` and emits `sbmlsim-page` with `{ page: "information" }` as any tab does, and the attribute set from outside shows it as well, so it can be linked and a page around the app can react to it (a page of the app which has the id `information` wins). The page which was shown before stays the current one underneath, with its selection, and its tab brings it back. The view ends in the slot `licenses`, which the page around the app fills with what it has to show there, the notices of the components it is built of among them; nothing of the element styles it, so the page writes and styles it as it writes the rest of itself, and the block is not drawn while the slot is empty. The parts are `nav`, `information-tab`, `information`, `information-title`, `information-subtitle`, `information-citation`, `information-doi`, `information-licenses`, `information-variants`, `information-run` and `information-host`.
- **A page may name scenarios.** A page with `scenarios` draws a select labelled `Example` which sets every knob a scenario names in one state.
- **A page may show the figure of the model.** A page with `figure` draws the `<sbmlsim-figure>` of the app beside its grid, in a column which starts at 560 px and grows with the shell to half of its width, at most 1100 px, so a wide window spends its room on the drawing as well as on the panels; below 1088 px of shell the figure is above the grid instead. The grid holds the panels of the selection, which starts as the panels the page declares as shown; a click on a part of the drawing adds the panels it opens and a second click removes them, and the drawing marks the parts every panel of which is shown. The panels stay in the order the page lists them, whatever order they were clicked in. Two parts may open the same panel; a click on a shown part removes exactly its own panels, and the other part, now only partly shown, is no longer marked. A part is named, to a screen reader, by the title of the panel it opens.
- **A page change resets the selection, with one exception.** A reader's click on a tab always starts the page from the panels it declares as shown. A `page` attribute set from outside keeps a `selection` which names a panel of the new page (an id the page does not list is dropped), since a deployment which sets it is restoring a state it chose; an empty `selection` stays empty, and any other value starts the page from its default. No `sbmlsim-selection` is emitted when the app first loads, and one is emitted whenever the selection falls back to what a page declares as shown: when a reader's click or a `page` attribute starts another page from its default panels, when a switch of the variant leaves a selection which names no panel of the page, and, for a page without the figure, only where a `selection` had been set, so a host which mirrors the selection into its address never keeps a stale value.
- **A page change swaps the panels.** The panels of the page which is left are frozen and removed, the ones of the page which is shown start themselves.
- **It follows the variant.** A switch of the variant reads the app again in it and passes it to every panel as its `variant`, holding the figures of the variant before, dimmed, until the new ones are drawn.
- **A failure leaves one line**, in the voice of the panel, and no navigation, grid or footer.

## `<sbmlsim-figure>`

The drawing of a model, which a reader clicks to choose what the app shows: an organ of a PBPK model opens the timecourse of that organ. The drawing is the `svg` of the figure of the app declaration, inserted as markup. It is trusted markup of the model package which assembles the app, the same origin as the declarations and the model, and it is not sanitized.

```html
<sbmlsim-figure id="figure"></sbmlsim-figure>
```

### Properties

| property | type                     | what it is                                                                                                                                                                      |
| -------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `figure` | `AppFigure \| null`      | the figure of the app (`svg`, `title`, `credit`, `panels`); `null` draws nothing                                                                                                |
| `marked` | `string[]`               | the key paths whose readouts are on screen, drawn as an accent halo around the element so the figure shows the state of the dashboard; a path which opens nothing is not marked |
| `labels` | `Record<string, string>` | the names of the key paths, the accessible names of the controls (`aria-label`); the key path itself where there is none                                                        |

Replace `figure`, `marked` and `labels` with a new value to change them: the element watches them shallowly, so `element.marked.push(path)` redraws nothing and `element.marked = [...element.marked, path]` does.

A key path is the `data-k` attributes of an element and of its ancestors joined with `/` from the outside in, `li` or `li/sub:gli`; a `data-k` which contains a slash is therefore ambiguous. `figure.panels` maps a path to the panels it opens, and a path with an empty list is a decoration. A click reports the longest path of the clicked element which opens a panel, so a click on a decoration inside an organ reports the organ, and a click on an element with no such path reports nothing. The elements which open a panel are controls (`role="button"`, focusable, Enter and Space, `aria-pressed` for the marked state) and the nesting of them is deliberate, at most two deep: a chip inside an organ is its own control. The element draws what it is told and does not decide what a click does, so a click on a marked path is reported like any other.

### Enlarging the drawing

A model drawing is dense and wide, and in the column of a page its labels are small, so the element shows it at the size of the window in a modal dialog. The button in the corner of the figure opens it, and so does a click on any place of the drawing which opens no panel, which is everything that is not a control. A click on a control of the enlarged drawing reports its path and closes the dialog, so a reader aims at an organ in the large drawing and lands back on the panels it opened; a click beside the drawing, the close button and Escape close it without reporting anything. The drawing is not copied into the dialog, it moves there and back, so the ids inside the svg stay unique and the controls and marks are the ones the page decorated.

### Events

| event                   | `detail`  | when                                                                 |
| ----------------------- | --------- | -------------------------------------------------------------------- |
| `sbmlsim-figure-select` | `{ key }` | a reader clicked or pressed a control; `key` is its path in `panels` |

It bubbles and is composed.

### Parts

`figure` (the whole figure), `drawing` (the svg), `zoom` (the button which enlarges it), `overlay` (the dialog of the enlarged drawing), `stage` (the box inside it the drawing moves into), `close` (the button which closes it).

## Failure kinds

The `kind` of `sbmlsim-error` is a short machine string, and the message is a fixed line per kind (`FAILURE_MESSAGES`), so nothing a server, a browser or a stack trace writes reaches the page:

| kind       | what went wrong                                                          |
| ---------- | ------------------------------------------------------------------------ |
| `network`  | the endpoint could not be reached (or the function of the page rejected) |
| `timeout`  | the endpoint did not answer within `timeout`                             |
| `busy`     | the endpoint shed the request every time it was sent                     |
| `http`     | the endpoint answered a status which is no success                       |
| `contract` | the payload is of another contract version                               |
| `body`     | the answer could not be read as the payload of its route                 |
| `internal` | the element itself could not draw what it got                            |

A request which was stopped (`aborted`), superseded by a newer one or stopped by `freeze()`, is no failure and dispatches nothing.

## The exports of the package

The module, and the global `sbmlsimWeb` of the IIFE bundle, export:

| export                                                                                           | what it is                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `register(tagName?, appTagName?, figureTagName?)`                                                | registers the elements under other tags (`sbmlsim-panel`, `sbmlsim-app` and `sbmlsim-figure` without); the shells place their panels under `tagName`; answers whether it registered anything |
| `registerEndpoint(endpoint, fetcher)`                                                            | registers the function which answers an endpoint `local:<name>` inside the page ([Endpoints](endpoints.md#an-endpoint-inside-the-page))                                                      |
| `PANEL_TAG`, `APP_TAG`, `FIGURE_TAG`                                                             | the default tags                                                                                                                                                                             |
| `SbmlsimPanelElement`, `SbmlsimAppElement`, `SbmlsimFigureElement`                               | the classes of the elements                                                                                                                                                                  |
| `figureOf(app)`, `showsFigure(page)`, `shownPanels(page)`                                        | read the figure of an app (`null` for none), whether a page shows it and the ids of the panels the page shows before any click                                                               |
| `PanelClient`                                                                                    | the client of an endpoint, the one place which calls `fetch` or a registered function, with `app`, `panel`, `data`, `simulate` and `stored`                                                  |
| `PanelRequestError`, `failureKind`, `FAILURE_MESSAGES`, `DEFAULT_TIMEOUT`, `LOCAL_PREFIX`        | the failures of a request, their lines, the default timeout and the prefix `local:`                                                                                                          |
| `CONTRACTS`, `checkContract`, `ContractError`                                                    | the versions of the contracts and their check                                                                                                                                                |

| `plotSvg(spec)`, `plotGeometry(spec)`, `seriesColour`, `tableMeasure`, `canvasMeasure`, `fontOf` | the renderer of a figure as one inline SVG string and its geometry                                                                                                                           |

The types of every payload (`PanelDeclaration`, `SimulateResponse`, `AppDeclaration`, ...), `EndpointFetch` and the element types `SbmlsimPanelHTMLElement`, `SbmlsimAppHTMLElement` and `SbmlsimFigureHTMLElement` are exported for TypeScript.
